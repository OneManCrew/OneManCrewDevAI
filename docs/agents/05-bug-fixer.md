# 🐛 The Bug Fixer Agent

> **Senior Bug Fixer & QA Specialist** · 30+ years of experience in debugging, root cause analysis, and software quality assurance across all technology stacks.

## Purpose

The Bug Fixer is the **fifth and final agent** in the pipeline. It analyzes bug reports from the user (or performs an automatic checkup of the generated build), creates structured bug tickets, assigns them to the appropriate coding agent, and orchestrates the actual fixes — writing corrected files to disk.

## Source Files

| File | Role |
|------|------|
| `src/renderer/services/bugFixerAgent.js` | Agent logic, prompt, bug report parsing, fix execution, persistence |
| `src/renderer/components/BugFixerChat.jsx` | UI component (chat interface, bug list, fix progress) |

## Phases

| # | Phase | Description |
|---|-------|-------------|
| 0 | **LOADING** | Loading project context (SRS, HLD, workplan, generated files) |
| 1 | **READY** | Waiting for user to describe a bug or trigger an automatic checkup |
| 2 | **ANALYZING** | LLM is analyzing the bug report and creating structured tickets |
| 3 | **FIXING** | A coding agent is executing the fix (writing files, running commands) |
| 4 | **DONE** | Fix completed — user can report more bugs or re-check |

## System Prompt

### Bug Analyzer Prompt

```
You are a senior Bug Fixer & QA Specialist with 30+ years of experience in
debugging, root cause analysis, and software quality assurance across all
technology stacks.

Your job is to:
1. Analyze the bug report and understand the root cause
2. Create a structured bug ticket with all necessary details
3. Determine which specialist agent should fix it
4. Provide clear fix instructions
```

The prompt lists all 6 available specialist agents and instructs the LLM to output structured bug reports.

### Bug Report Output Format

The LLM outputs bug reports as fenced JSON blocks:

```
```bug-report
{
  "title": "Short descriptive title",
  "severity": "critical|high|medium|low",
  "description": "Detailed description of the bug",
  "rootCause": "Analysis of what's causing the bug",
  "affectedFiles": ["path/to/file1.js"],
  "assignedAgent": "backend|frontend|devops|testing|integration|setup",
  "fixInstructions": "Step-by-step instructions for the fixing agent",
  "fixTask": {
    "title": "Fix: Short title",
    "description": "What needs to be changed",
    "acceptanceCriteria": ["Criterion 1", "Criterion 2"]
  }
}
```​
```

Multiple bug reports can be output in a single response.

### Automatic Checkup Mode

The `buildCheckupMessage()` function generates a special user message that instructs the Bug Fixer to perform a systematic review:

1. Check if all planned tasks/features were actually implemented
2. Look for missing files, incomplete implementations, broken integrations
3. Verify acceptance criteria are met
4. Check for common issues: missing event handlers, broken imports, missing dependencies
5. Create a `bug-report` block for each issue found

The checkup message includes the full workplan (all phases, tasks, and acceptance criteria) and the list of generated files.

### Fix Execution Tools (delegated to Coding Agents)

When a bug fix is executed, the Bug Fixer delegates to the appropriate coding agent via `executeBugFix()`, which uses the same tool infrastructure as the Coding Agents:

| Tool | Type | Description |
|------|------|-------------|
| **Write File** | ```` ```file:path ``` ```` | Write/overwrite a source file (via `safeWriteFile` with file locking) |
| **Run Command** | ```` ```exec-command {...} ``` ```` | Execute a shell command (via sequential queue, 300s timeout) |
| **Request Input** | ```` ```need-input {...} ``` ```` | Ask the user a question |

Fix execution also benefits from the same infrastructure as Stage 4:
- **Syntax Validation** — `node --check` on `.js`/`.jsx` files with auto-retry (max 2)
- **Safe File Writes** — `FileLockManager` prevents concurrent writes
- **Command Timeout** — 300s timeout with process tree kill on stuck commands

## Fix Execution Flow

1. User describes a bug → LLM analyzes and outputs ```` ```bug-report ``` ```` block(s)
2. Bug reports are parsed by `parseBugReports()` and added to the bug list
3. User triggers fix → `executeBugFix()` is called:
   - Builds a task object from the bug report (title, description, root cause, fix instructions, affected files, acceptance criteria)
   - Assigns to the specialist agent specified in `bug.assignedAgent`
   - Delegates to `executeTask()` from `codingAgents.js` (same infrastructure as Stage 4)
   - Files are written to disk in real-time via `safeWriteFile` (with file locking)
   - Commands are executed via sequential queue (300s timeout)
   - Syntax validation runs on every `.js`/`.jsx` file with auto-retry
   - Logs are written in real-time via `TaskLogger`
4. Bug status is updated: `open → in_progress → fixed` (or `failed`)
5. Results are persisted to `bugs.json`

## Bug Severity Levels

| Severity | Description |
|----------|-------------|
| `critical` | System crash, data loss, security vulnerability |
| `high` | Major feature broken, significant user impact |
| `medium` | Feature partially broken, workaround exists |
| `low` | Cosmetic issue, minor inconvenience |

## Key Functions

| Function | Description |
|----------|-------------|
| `parseBugReports(output)` | Extract all ```` ```bug-report ``` ```` JSON blocks from LLM output |
| `stripBugReportBlocks(output)` | Remove bug-report blocks from text (for display) |
| `buildBugFixerMessages(chatHistory, projectContext)` | Build conversation messages with project context |
| `buildCheckupMessage(projectContext, workplan, fileList)` | Generate automatic checkup instruction message |
| `executeBugFix(bug, projectContext, settings, projectPath, callbacks)` | Execute a fix via the coding agent infrastructure |
| `saveBugs(projectPath, bugs)` / `loadBugs(projectPath)` | Persist/load bug tracker to/from disk |
| `saveBugChatHistory(projectPath, history)` / `loadBugChatHistory(projectPath)` | Persist/load chat history |
